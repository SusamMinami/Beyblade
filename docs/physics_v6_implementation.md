# 第三轮：共享物理 v6 与 Godot 接入

2026-09-24 开始实施。继承 [前两轮 v5](physics_v5_implementation.md)，先在 Web 验证，
再接入 Godot。本轮组合版本：`2026.09.24-shared-v6+launcher-v1`。
本文描述已实现内容；数值、运行截图和检查日志见 [验证记录](../.impeccable/review/physics-v6/verification.md)。

## 已实现

### 地面、边缘与装配高度

- Web `arena-contact.js` 和 Godot `v6_data.gd` 共用同一高度轮廓及中心差分法线。
  坡面加速度取重力沿曲面的分量，替换与画面高度无关的径向拉力。
- 复合场的高度拼接使用 Hermite 曲线，在内部两处接缝保持高度和一阶导数连续。
  金属场保留可见的径向浅碗与六向微起伏，不再使用旧 Godot 的单向斜坡。
- 圆场外缘为宽 `0.24`、高 `0.16` 的圆顶低边沿；由坡面逐步减速，
  不再瞬移位置或反射速度。Godot 地形网格额外用八圈分辨边沿，移除旧高护墙。
- 方形遗迹直接采用开放边缘。丢失支撑后记录下落高度／速度／距离，
  不能空中操控、吃供能或再次碰撞反弹回地面；下落达到阈值或越过外界线判 Ring Out。
- `assemblySupport` 根据五件装配锚点、剩余质量及实际轴尖底部计算支点至质心高度，
  替换接地模型中的经验高度 `0.14`。三种轴尖及不同 DIY 高度均用实际模型包围盒校验。
  两端战斗模型比例为 `0.92`，支点有 `0.012` 的显示间隙。
- 每个 `1/60s` 规则步拆为两个 `1/120s` 接触子步，以减少短时接触遗漏。
  这仍是离散子步，**没有宣称实现扫掠 CCD**。

### 手感与显示一致性

- 摇杆径向死区为 `0.035`，死区之外连续映射到满推力；松手立即归零。
  屏幕输入在当前相机边界转换成世界指令，求解器保持与镜头无关。
- 两端会话统一固定步长累计器；30／60／120Hz 渲染批次产生相同完整状态。
  暂停、失焦及恢复会清除残余输入和时间积累，不在回到窗口时补跑一串旧操作。
- Godot 使用 `qTilt × qSpin`，有符号自旋与倾斜方向相互独立，
  旋转一周不会周期性竖直，轴尖固定在当前地面支点。
- Godot 战斗页显示实际换算 `ω × 60 / 2π` 的 RPM，渲染也使用同一角速度；
  质量和尺寸继续使用游戏平衡单位，不代表实物尺寸标定。
- 五部件八扇区的损伤、结构刚度／惯量、接地滑移、旋转碰撞、供能区争夺、
  AI 和胜负裁决均接入原生场景；五张地图可从原生地图页进入。
- 同步停转判平局，原生结算不给金币、不记败局、不推进训练；音频更新延后调度，
  与规则推进分离。右键拖动可绕场检查方向与轴姿态。

### 完整恢复与本地回放

Web：`exportState()`／`restoreState()`，`battle-replay.js` 提供记录、播放和固定时钟。
Godot：`export_state()`／`restore_state()`，`BattleSession.local_replay` 自动记录本地输入，
`restore_local_state()` 从合法中间状态续算。

完整格式包含规则及装配上下文、发射器、保养派生量、种子、帧、时间、调参、
双方轴状态、旋转相位、结构扇区、接触历史、下落、供能、统计、事件和结果。
恢复前检查版本、上下文、有限数值、必要字段与类型；拒绝时不修改当前对局。
Godot JSON 输出需保留双精度：`JSON.stringify(state, "", true, true)`。
旧的诊断快照及二进制网络快照不满足该契约。

这是开发与回归使用的本地恢复／回放 API，未增加面向玩家的回放库或云端续局界面。
它不证明客户端提交可信，也不负责金币、库存或服务端权威结算。

## Godot 的实现分层

正式对战结算始终由共享求解器负责。`BeybladeBody` 及
`tests/battle/collision_damage_test.gd`、`spin_mobility_test.gd`
保留用于 Godot/Jolt 实体碰撞、部件脱落、动态质心与手感实验。
实验体碰撞回调不反写正式胜负、伤害或联网状态；其参数不是正式求解器的调参入口。
规则修改先在 Web 验证，再迁移下列原生实现并更新跨端金标。

| 文件 | 职责 |
| --- | --- |
| `scripts/battle/v6_data.gd` | 正式资源／DIY 计算桥接、共享场地与发射器数据、向量工具 |
| `scripts/battle/v6_dynamics.gd` | 结构、惯量耗散、接地、轴响应、旋转接触 |
| `scripts/battle/v6_launcher.gd` | 发射器有限能量与润滑效果 |
| `scripts/battle/v6_simulation.gd` | 双精度规则、AI、子步、裁决、完整状态 |
| `scripts/battle/battle_simulation.gd` | 兼容现有资源与 snake_case／Vector2 API 的场景适配层 |
| `scripts/battle/battle_session.gd` | 固定步长、本地回放和会话状态 |
| `scripts/battle/v6_presentation.gd` | 相机输入、姿态与贴地供能区几何 |

规则内部用 Dictionary 保存双精度标量；标准 Godot 的 Vector2／Vector3 使用单精度，
只放在场景边界。两端对照使用真实 JS 与 GDScript 各自执行，未在 Godot 内调用 JS。
`resources/physics/v6_catalog.json` 由实际 Web 数据导出，原生零件仍来自正式 15 件资源，
没有另建库存或修改价格。

## 验收入口

Web 在 `web-prototype/` 启动 `npm run dev`。Godot 打开根目录 `project.godot`，
从组装页进入地图与战斗；也可直接运行 `scenes/battle/BattleScreen.tscn`。

建议手动复核四种反馈：

1. 轻推、全推、松手，再绕场 90° 重复，确认方向和响应连续。
2. 同一发射比较橡胶尖／金属尖的抓地、滑行和撞后摆动。
3. 低速压上圆场边沿，再在遗迹冲出边缘，观察减速与下落。
4. 接触后争夺供能区，确认结构损伤不因补转消失；暂停切窗后恢复。

这些主观判断不能由自动测试替代。本轮保留已有零件、价格与成长计算；
未为追求“更爽”而普遍提高推力、碰撞或续航。

## 明确边界

- 已移植的是**本地战斗规则及原生场景接入**。Godot 街头／遗迹使用匹配碰撞的程序几何，
  尚未移植 Web 的完整 Blender 场景、湿材质、动态灯光和发射器动画机构。
- Godot 求解器可接收等价 `launchers`／`maintenance` 规则参数，但原生换装／涂油工作台、
  Web 库存存档互迁、测量评分界面和剧情系统尚未整套迁移。
- 网络仍为旧 `2026.07.21-bin`。两端 Provider 明确拒绝 v6，
  Worker、二进制编码和权威验证未升级，不能据数值对照通过宣称跨端联机已完成。
- 轴响应仍是有阻尼的降阶模型，没有完整三维刚体角动量、横向转动能、
  真实有限元损伤或独立碎片。低边沿也未引入完整离地抛射；不能称为全三维能量守恒。
- 每次渲染最多计入 `0.05s`，严重卡顿时模拟时间会慢于墙钟，避免恢复时突然追赶。
- Godot `BeybladeBody` 的 Jolt 实验继续保留，正式对战结算由共享求解器负责。
