# 游戏流程：从操作到成长

适用：Web 原型。核对与新一轮修复：2026-09-30。
本页合并前两轮流程说明，集中区分**已实现行为、当前修复与未实现提案**。
人物与十关内容见 [回声远征](campaign_direction.md)，
房间与工具边界见 [共享组装实验室](home_lab_integration.md)。

## 原设计应形成的闭环

```text
发射训练 → 首次购买 → 改装验证战 → 我的陀螺基地
                                      ↓
结果与下一站 ← 发射/操控/抢区 ← 当前约战
     ↓                            ↕
读懂原因 → 改装 / 发射器 / 保养 / 测试 → 返回同一约战
```

玩家始终操作自己的真实配置；实验与改装有可解释的收益/代价，
主线提供下一名对手与关系变化。保养和实验可选，选做挑战不阻塞剧情；
不通过强制消费、永久损坏或刷数值制造继续游戏的门槛。

## 已实现的行为契约

| 环节 | 当前行为 | 验收要点 |
| --- | --- | --- |
| 初次游戏 | 首战、首次改装、第二战；可以显式跳过 | 改装认可已装备的付费陀螺件/发射器件；首战非平局一次 180 金币，普通胜/败 120/40 |
| 学操作 | 发射、轻推、追踪亮区逐步提示 | 真实操控/补转后才确认完成；提示不阻止比赛 |
| 选任务 | 前置对手、目标、配置；剧情和情报折叠 | 未开放关卡可预览但不能出战；第一关非平局可推进，其余需获胜 |
| 战前准备 | 同标签页保存可挑战任务，改装/测试/陈列可返回 | `sessionStorage` 的 `spin-core-preparing-mission`；重打旧关与刷新仍保持目标 |
| 改装与保养 | 原组装内切换真实陀螺、发射器、保养与房间 | 已购买所有权立即存；装备/油膜草稿保存才生效 |
| 配置成长 | 每槽保存最近一次已结束比赛的实际零件/DIY 快照 | 不跨槽借记录；弃赛不覆盖；旧档无记录显示空状态 |
| 比较取舍 | 改装、任务与结果共用配置对比 | 续航/耐久固定条件实测，其余属性换算；不把评分等同胜率 |
| 结算 | 根据自己的出界、损伤、占区给建议；战报可展开 | 检查建议只定位真实部位，不替玩家购买或装备 |
| 章节回应 | 五章首通人物回信、下一站、任务页回看 | 重打不重复首通；旧档按完成事实恢复，不发额外奖励 |
| 中断 | 待发可返回；运行中计时器/Escape 暂停；失焦自动暂停 | 清空输入；主动继续；退出不发奖、不推进、不写完成战历 |
| 平局 | 解释原因并提供重赛 | 不发金币、不推进训练/主线；保存已结束战历与配置参照 |

准备目标只能来自已解锁且可挑战的任务。明确选择自由模式或开始对局会清理旧目标；
结果后去准备应建立该场任务的目标。不能把“看过的未来关卡”作为可出战凭据。

保存继续遵循已确认设计：保存留在当前工具；同页工具/房间切换保留草稿；
离开组装放弃未保存草稿；撤回返回原陀螺组装。已完成购买不会随撤回取消。
这些行为必须在离开操作上可理解，并在保存失败时保留草稿和之前装备。

## 本轮检查与修复

2026-09-30 双独立检查后，已在 Web 实现以下五组修复：

| 修复前阻碍 | 已落地行为 | 验证 |
| --- | --- | --- |
| 首战 180 金币买并保存 R03 后仍要求首次购买，余额已归零 | 陀螺商店、实验室商店、发射器保存共用实际装备判定；成功保存发射器后进入第二战，文案点名型号 | 未拥有预览、购买失败、购买后撤回、保存失败都不误推进；旧已装备卡住存档恢复 |
| 发射器/保养隐藏了原组装的返回约战 | 工具固定底栏同时提供返回约战/训练与保存；保存留当前模式，未保存状态说明离开后果 | 重打第一关→工具→同一约战；保存与放弃草稿分别检查 |
| 手机测试室底栏覆盖 V3 零件卡片 | 两个底栏动作并排，零件三卡完整留在上方 | 390×844、320×568、1440×1000 的卡片与名称中心命中正确 |
| 极简测试室默认近景不显示结果 | 无实体仪表的极简房间在近景/俯视持续显示同一份实际配置读数 | 检测、通知消失、切视角后仍可见；报告与30 XP规则不变 |
| 手机导航只剩无名称圆点、顶部对战无响应、帮助被风场挡住 | 中文导航和44px目标、对战接约战/训练；工具2×2分组，极简房间使用深色文字，读数避让标签 | 两种手机尺寸与桌面，实际指针打开帮助，导航返回正确 |

新增 `npm run verify:continuity` 的 **69 项**检查全部通过。
本轮未调整价格、库存、实验经验、战斗物理、AI 难度或场景资产。
自动化前后图和完整检查结果见[本轮验证记录](flow-audit/2026-09-30/verification.md)；
其中买件布局对照的余额/教学状态不同，仅用于比较遮挡。

体验判断：设计的主要功能已具备，首要问题是相邻功能间丢失上下文、完成后缺少
明确下一步。现已接通“真实改装→保存→同一场对战”和“试验→看到数值→返回”。
真实玩家能否理解取舍、是否觉得值得反复玩，仍需试玩，而非由自动化评分推定。

## 后续落实顺序

| 优先级 | 目标 | 落地方式与完成条件 |
| --- | --- | --- |
| P2 | 验证新手真的理解第一次改装 | 试玩陀螺件、发射器件两条教学路线，记录看不懂的操作与中断点；保留显式跳过，不强迫二次消费 |
| P2 | 反馈帮助玩家决定下一次尝试 | 从实际发射、接地、损伤和占区数据给动作建议；保持一条主要建议 |
| P2 | 全程节奏与难度可学 | 人类试玩前两场及五章，记录失败原因和停留；再调参，不为文案改物理 |
| P2 | 旅途纪念成为可见的共同经历 | 复用真实战历/章节纪念，扩展陈列室查看；暂不增加任务计数负担 |
| P3 | 玩家回放与更丰富支线 | 基于现有完整恢复工具接记录/播放；支线有起止与选择，不冒充已完成 |

没有把公网排位作为此次单机流程修复前提；其前置工作独立见
[PVP 接入缺口](network_pvp_architecture.md)。
