原模型 193 个独立网格、五个建模 Collection，但 Web 导出按材质合成七个网格，
同一蓝色材质同时用于外壳、齿轮、卡口。它适合整件绘制，但无法安全地按功能
替换零件，直接改蓝色会连内部件一起改色。

本次按「模块 + 材质用途」重组，不增加几何。模块导出保留八个根节点和换色区
标记，同一模块内部仍合批。`TopMount` 及第 1 帧的装配坐标保持不变。
网格数量、面数和字节数以生成的 `modules.json` 为准。
当前模块导出为 29 个材质批次、27,560 三角面、779,372 字节。批次数增加
是保留模块替换和换色边界的代价；未来只在发射准备 / 改装时显示，并继续按
模块内部合批。尚未测量模块版进入游戏后的 GPU 耗时。

## 八个可替换槽位

| 编号 / 模块 | 现有网格数 | 纳入部件 | 适合的替换方向 | 性能升级判断 |
| --- | ---: | --- | --- | --- |
| 01 机身外壳 `housing` | 22 | 上下壳、护肩、侧筋、固定导轨、盖板支撑柱 | 外形、包覆、防护风格、配色 | 首期外观项；不凭空增加陀螺攻防 |
| 02 检修上盖 `cover` | 24 | 透明片、框、加强筋、侧扣、四角螺丝与标记 | 透明 / 半透明 / 封闭式、不同边框 | 首期外观项；可视性与外观取舍 |
| 03 主握柄 `grip` | 32 | 骨架、掌心胶垫、侧轨、防滑纹、尾托 | 不同长度、厚度、握持形状 | 手感候选；当前没有握持误差模型 |
| 04 抽拉柄 `pull_handle` | 9 | T 形柄、胶垫、端盖、与齿条连接头 | T 形 / 环形 / 双指等形状方向 | 手感候选；需先确定实际抽拉交互 |
| 05 驱动齿条 `rack` | 51 | 壳内外齿条、齿、加强条 | 行程、刚性、传动损耗取舍 | 第一批性能候选 |
| 06 传动芯组 `transmission` | 32 | 托板、输出轮、两枚小齿轮、轴 / 轴座、回位弹簧 | 成套变速、惯量适配、传动效率 | 第一批性能候选；整组匹配替换 |
| 07 陀螺连接头 `coupler` | 18 | 输出套筒、金属肩、卡口、三爪、外缘筋 | 同心度、锁合、脱离结构 | 第一批性能候选；先统一陀螺兼容接口 |
| 08 释放开关 `release` | 5 | 开关底座、滑钮和防滑筋 | 释放行程、锁止 / 回位结构 | 预留槽位；内部功能结构尚缺 |

193 个网格全部归属上述槽位且只出现一次；`TopMount` 为额外定位空物体，
随 07 连接头分组，不计入网格数。编号用于这次拆分说明，不代表品质、升级顺序
或玩家需要购买 193 个小零件。

### 为什么把传动装成一个芯组

齿轮的模数、齿数、中心距和轴高需要相互配合。第一批让玩家替换一套芯组，
其内部齿轮、轴承表现和回位弹簧随部件升级；建模上仍保留独立对象供后续动画。
如果让每枚齿轮随意混装，必须新增兼容规则、齿距校验与错误组合反馈。
待核心玩法成立后，再决定是否开放芯组内部的深度改装。

当前齿形、弹簧和齿数来自视觉建模，不是已验证的机械传动设计，不能直接
把网格上的齿数当成游戏倍率。回位弹簧服务于回位结构，也不应自动解释为
“弹簧越强，陀螺转速越高”。

## 外壳自由换色

蓝白与红黑使用同一模型、同一套部件。红色参考是配色依据，红色不代表
更高等级或不同性能。换色只改基色，保留原来的粗糙度、金属度和透明度。

| 换色通道 | 覆盖范围 | 处理方式 |
| --- | --- | --- |
| 主色 `primary` | 护肩、头部护壳、盖框、握柄装饰、T 柄主体 | 自由 RGB / 色盘；支持整套联动 |
| 辅色 `secondary` | 主壳侧面、握柄侧轨、颈部桥、T 柄端盖 | 与主色独立 |
| 底壳 `chassis` | 深色下壳、接缝、握柄骨架与开关底座 | 高级调色区域 |
| 胶垫 `grip` | 掌心垫、指槽、拉柄胶垫 | 可染色但保留粗糙橡胶质感 |
| 小件 `accent` | 解锁滑钮 | 独立强调色 |
| 视窗 `window` | 透明盖及加强筋 | 仅染色；透明度由盖板部件决定 |

传动齿轮、轴、螺丝、齿条受力面和卡口暂不跟随外壳换色。它们的颜色与
材料表现属于各自部件。标识文字另有对比色材质，避免红黑配色后文字消失。

建议未来界面默认显示主色、辅色、胶垫；展开后调整底壳、小件和视窗。
“应用到整套”统一主色；按模块改色使用覆盖值。替换零件默认继承玩家已有
配色，并允许恢复新零件出厂色。纯换色免费，外形替换 / 材质方案与性能升级
按实际部件管理，避免把每种颜色做成独立库存。

本阶段只验证了材质区域隔离和两套配色渲染；上述色盘和保存交互尚未进入游戏。

## 装配接口：可拆分与真正可互换的差别

现在每个模块都有独立根节点，可隐藏、移开、替换整组网格。原模型一些接合处
仍是贴合或穿插表面，尚未绘制完整隐藏连接结构。下一阶段需先补以下内容：

| 接口 | 当前依据 | 新部件必须统一的约束 / 待补项 |
| --- | --- | --- |
| 外壳 ↔ 芯组 | 齿轮箱开口、现有托板 | 统一内部包络、固定孔和输出轴位置 |
| 外壳 ↔ 上盖 | 四角螺丝、已有盖框 | 统一螺丝孔位及密封接触面 |
| 外壳 ↔ 主握柄 | 颈部与主壳接触区域 | 补插榫或滑轨、定位肩、紧固结构 |
| 导轨 ↔ 齿条 | 已有穿壳口和直齿轨迹 | 统一导轨截面、齿距和可用行程 |
| 齿条 ↔ 抽拉柄 | 现有连接头 | 补可拆连接销 / 卡扣，不用表面相交冒充接口 |
| 芯组 ↔ 连接头 | 共用输出中心轴 | 补标准上端传动接口与快拆固定方式 |
| 连接头 ↔ 陀螺 | `TopMount = [0, -0.474, -0.12]` | 保持输出中心和现有实际陀螺顶部对齐 |
| 释放开关 ↔ 连接头 | 只有外部滑钮 | 补拨杆 / 凸轮、卡爪联动和回位；先确定动作 |

锚点采用 Web 视觉单位；源清单同时保留模块锚点与拆解位移。它们用于场景
装配，不是毫米尺寸规范，也不代表已经完成可制造性验证。

## 下一阶段的部件设计依据

本节是第一阶段提出的方向；九款部件的实际模型与当前边界见
[性能部件设计](launcher_performance_parts.md)。

建议先围绕 05 齿条、06 传动芯组、07 连接头设计“均衡、速转、稳定”三种
方向，再配套 03 / 04 的握持外形，以及 01 / 02 的蓝白和红黑外观。
这只是方向，还没有定义具体 SKU、数值、价格或解锁门槛。

性能需落到可测的发射结果，例如有效初始转速、拉动工作量、释放倾斜，
同时设计取舍。高传动比可能要求更快 / 更大的输入，也可能不适合高惯量陀螺，
不能让所有属性随等级一起上涨。稳定型也不能通过人为制造基础件随机失误
来显得更强。

当前求解器 `BattleSimulation.launch()` 接收 `power / height / direction / angle`，
转速还取决于陀螺自身的 `maxSpinSpeed`，前进速度使用 `launchForwardImpulse`。
发射器尚无属性、误差或抽拉手势模型。未来若增加齿比、效率和释放稳定度：

1. 保留现有陀螺计算，只在明确的发射输入 / 初始条件处接入发射器；
2. 同步单机与 `launchExplicit()`，将发射器配置纳入双方对局快照与版本边界；
3. 复用现有三出战槽、金币、购买确认与所有权框架，扩展合法部件注册及存档
   迁移；不能把新的发射器 ID 直接塞进只识别 15 个陀螺零件的注册表；
4. 外壳颜色不进入战斗强度计算，但必须进入外观缓存和预热配置键。
