# 战斗陀螺 Web 验证原型

独立的 HTML / Three.js / Tone.js 版本。所有网页版源码、测试和依赖声明均位于
`web-prototype/`，不依赖 Godot 运行时。

**当前迭代顺序：先实现并验证 Web，再同步 Godot。** 新增界面系统可以逐步实现；
尚未接通的服务明确显示状态。此约定已写入根目录 `AGENTS.md`。

组装与场景入口核对：2026-09-30。[按任务查找文档](../docs/README.md)；
视觉规范见 [DESIGN.md](DESIGN.md)，模型和地图见 [场景说明](../docs/battle_worlds.md)。

场景加载已改为按需准备：同一地图预览与比赛复用场景，未改变的陀螺和缩略图
直接复用。进入其他地图仍释放旧场景，实验室/展示舞台按选择加载。
首次材质准备仍需要时间，结果与后续空间见
[加载诊断与测量](../docs/scene_loading_performance.md)。
地图稳定后会在空闲时间预热实际下一场陀螺、发射器和材质；换图、换配置或离开
会取消。预热尚未完成也可直接准备发射，沿用正常加载流程，不影响存档或进度。
`npm run verify:loading` 检查缓存、失败重试及异步切换；
`npm run measure:loading -- <记录名>` 记录固定路径进入耗时，需要 dev server 和 Chrome。
`npm run verify:gpu` 检查预热采用、取消和 GPU 资源释放；
`npm run measure:gpu -- <记录名>` 分别记录首次准备及停留阅读后的开战耗时。

战斗发射器已替换为 Blender 制作的蓝白分体外壳、透明机械盖、齿轮齿条与
防滑握柄模型。打开 `/#map` 选择场地并进入发射准备即可查看，操作方式不变。
源文件、重建与加载边界见 [发射器模型](../docs/battle_worlds.md#发射器模型2026-09-23web-已接入)；
`npm run verify:launcher` 检查模型、定位、发射与资源回收。

## 统一组装与发射器换装

打开 `http://127.0.0.1:5173/#assembly`。原三陀螺切换、五件换装、点选模型与 DIY
保留，顶部工具栏切换“陀螺 / 发射器 / 保养”，右侧场景菜单选择实验室。
旧 `/#launcher`、`/#maintenance` 分别映射到发射器、保养模式，地址归一为 `/#assembly`。
所有模式沿用原纸色／黑字／蓝色控件，共享测试室的真实场景和渲染器。

点击“发射器”展开实际模型，支持三槽九件混搭、已有金币购买和外壳／装甲／握柄
自由换色。锁定件只预览；购买保存所有权，装入草稿后点“保存换装”才装备。
保存后留在当前模式；内部切换工具或房间保留草稿。
“撤回未保存修改”恢复草稿并返回陀螺组装；离开组装放弃未保存修改，
已经完成的购买保留。

发射器或保养底部可直接返回正在准备的约战；草稿区会说明离开组装将放弃未保存
修改。首次改装支持陀螺零件与发射器零件，成功装备/保存后进入第二场训练；
仅预览、购买后撤回、换色或上油不算完成改装。旧档已保存发射器升级却仍卡在
购买阶段时，载入后恢复到第二场。手机顶部导航保留文字，零件卡片与底栏分行。

对照试拉显示真实转速、抽拉负担、输入做功和释放耗时。正式发射按齿比驱动
齿条／齿轮，释放叉、凸轮环与三爪脱扣后开战，性能受同一能量预算限制。
旧档默认参考三件，保持原有发射结果；颜色不影响性能。
`npm run verify:launcher-outfit` 检查 27 种混搭、经济边界及桌面／手机实际操作。
`npm run verify:assembly` 检查原点选与 DIY、三陀螺切换、草稿、场景升级、

实现细节和机械近似见[发射器运行时](../docs/launcher_runtime.md)。

## 同页保养

组装工具栏点击“保养”；实验室/主页的“改装保养”同样进入原组装的保养模式。
使用当前极简空间、童年书桌或精密实验室，保存后留在当前模式。
零件自动展开，可直接拖动滴油、擦拭，随时撤销或擦净；上方部位按钮移近观察，
双指/右键拖动环绕、滚轮缩放。“环绕”工具也支持单指观察。
键盘聚焦模型后，方向键环绕、加减号缩放、Enter 在准星处滴油或擦拭。
准星会贴近所选零件的真实可见表面，避开展开结构中间的空隙。

适量传动油可减少损耗，过量增加拖曳；握柄/拉柄油污分别影响支撑和有效拉力；
轴尖沾油降低抓地和制动。外壳和固定部件可涂抹，只留下表面油膜。
“对照试拉”调用实际求解器比较进入时与当前草稿，数据用游戏平衡单位。
“保存保养”才写入本机存档并应用到下一场对战，“撤回未保存修改”放弃草稿。
保养免费，不消耗库存或经验。内部自由活动的陀螺部件后续补齐。

`npm run verify:maintenance` 运行数值因果与隔离 Chrome 操作检查，需要 dev server。
独立数值检查可运行 `node tools/verify-maintenance-physics.mjs`。
物理近似、模型来源、保存边界和未实现项见 [保养说明](../docs/maintenance_lubrication_design.md)。

极简测试室在近景、俯视均显示真实配置读数，通知消失后仍可查看；
测试记录、经验和测量公式保持原规则。`npm run verify:continuity` 检查本轮
教学、存档恢复、保存失败、返回约战与桌面/手机/短屏可达性。
完整结果与后续工作见[流程说明](../docs/game_flow_optimization.md)。

  续航／耐久采用固定条件实测，攻击／稳定／控制保留属性换算。
  同时列出零件替换或 DIY 变化；评分表示配置取舍，不保证实战胜利。
- 本机 v2 存档增加 `battleNotes`，每个出战槽只保存最近一场已结束比赛的真实配置与 DIY。
  弃赛不覆盖，其他槽不借用记录；旧存档没有记录时明确显示空状态。
- 每章首次完成的结算显示人物回应与下一站入口；任务页“同行人的回信”可回看已解锁内容。
  重打不重复首通回应，未完成章节不显示回信。
- `npm run verify:growth` 在隔离存档验证完整两场训练、购买取消、配置对比、刷新、
  弃赛保护及章节解锁边界；需要 dev server 和 Chrome。支持 `GROWTH_CAPTURE=0` 跳过截图。

实现、当前阻碍与验收边界统一见 [流程优化](../docs/game_flow_optimization.md)。

## 抢区与结构损伤

- A/B/C 加速区每八秒轮换：七秒供能、一秒冷却。跟随亮区并反向轻推刹车，可停留补转。
- 同时入区会分摊供能，撞开对手可独享。供能有限且不修复破损，停止旋转后不能复活。
- 真实五零件分别记录八个方向的局部损伤。碰撞与撞柱会改变重心、惯量和刚度；
  材料、尺寸、厚度与凸翼影响抗损。严重偏心会持续擦地掉转，即使留在加速区也可能失速。
- 模型按受撞方向产生局部形变。顶栏显示最重损伤/结构失衡，结算显示原因、
  占区时间、补转量、交锋次数，并可展开双方五零件的最重局部损伤。
- 一般动态模式保留 850ms 终结镜头后展示报告；减少动态模式直接显示结算。
- 损伤每回合重置，仍使用已有库存、DIY、金币和奖励。原型为游戏平衡单位近似，
  不是工程有限元。详细规则见 [Web v4 设计](../docs/structural_battle_design.md)。
- `npm run verify:structure` 验证物理因果与 AI；`npm run verify:battle-ui` 验证实际对战、
  手机布局及模型样本，需要 dev server 和 Chrome。

## 比赛场景与日夜

`/#map` 或 `/#journey` 顶部可选择“随本地时间 / 白天 / 夜晚”，五张地图都支持，
选择随本机存档保存并带入比赛。自动模式在进入场景时解析，6–18 时为白天，
一场比赛中不随时钟突变。

街头生活物件已按陀螺比例重做：车轮约为默认陀螺直径的 11 倍，门高约为 34 倍。
战斗近景保留盘面，以车轮、花盆、门槛的局部建立日常尺度。白天有日光与天空反射，
夜晚有暖店灯、湿地反光和微幅环境动态。建模、灯具锚点及复查说明见
[场景说明](../docs/battle_worlds.md)。运行 `node tools/verify-street.mjs` 检查街头比例、
日夜持久化及反射资源；支持与其他浏览器检查相同的 `LAB_TEST_URL` / `CHROME_PATH`。

- 15 个正式零件和 `3^5 = 243` 种组合。
- 与 Godot `AssemblyCalculator` 对齐的质量、惯量、摩擦、续航、控制、攻击和耐久计算。
- 五张竞技场：标准碗形、冠军科幻（原金属高速）、复合材质、街头、浮空遗迹。
- 确定性固定步长 1v1 模拟、基础 AI、虚拟摇杆和键盘控制。
- 3D 发射器直接操作：拖动模型调方向与倾角，拖动箭头端点调方向和力度。
- Spin Out、Ring Out、Break 和超时判定。
- Tone.js 发射、旋转、碰撞与结算动态音效。
- 碰撞伤害、转速衰减、控制响应和移动速度实时调参。
- 配置、颜色、赏金、地图和调参结果本地保存。
- 白纸、黑色粗线、电蓝与橙色构成的涂鸦式准备界面。
- 固定 `9:16` 竖屏画布，组装模型作为主视觉，信息沿画面边缘分布。
- 组装页默认只显示陀螺；点选部件后才展开改装，其他部件自动半透明。
- 三个独立出战槽位支持左右横扫切换，并分别保存配置和颜色。
- 地图选择使用横向吸附卡片，一屏完成切换。
- 组装模型支持统一环绕视角、滚轮/双指缩放和视角复位。
- 15 个零件的价格、所有权、金币购买、余额不足反馈和性能差值确认。
- 战斗优先的新手训练：木质陀螺首战、固定金币奖励、首次购买和改装验证战。
- `v2` 本地存档保存零件所有权和教程进度，并兼容迁移 `v1` 配置。

- 摇杆固定在战斗画面底部；陀螺上方只显示实时控制影响与施力方向。

  高度和轮廓起伏。
- DIY 顶栏提供正视、俯视、侧视、实时质量/惯量和 2 / 3 / 4 / 6 边对称延展；

## 操作

- 组装：轻点模型选择具体部件，未选中的部件会变为半透明；轻点空白退出改装。
- 深度 DIY：再次点击已装备零件进入编辑；保存后写入当前出战槽，取消则丢弃草稿。
- 模型塑形：拖蓝色手柄改大小，拖橙色手柄改高度，拖红色手柄改轮廓起伏。
- 视角：在模型或背景上拖动都会环绕整个场景；滚轮或双指缩放。点击其他部位会
  平滑移动镜头并直接切换编辑目标。
- 出战槽：在空白区域横扫，或点击顶部左右触控区域切换三个陀螺。
- 解锁：灰色零件尚未拥有；金色钱币标记表示余额足够，点击后确认购买并自动装备。
- 地图：左右滑动卡片切换竞技场，底部只有一个确认按钮。
- 发射：拖动发射器/陀螺改变方向和倾角；拖动黄色箭头端点改变方向与力度，
  箭头长度即力度。
- 战斗：摇杆固定在屏幕底部；陀螺附近只显示控制影响，桌面仍支持
  `WASD` 或方向键。
- 新手训练：首次访问从木质陀螺战斗开始，可随时点击“跳过引导”退出训练。

## 技术说明

战斗逻辑使用固定 `1/60s` 步长的确定性二维模拟，Three.js 只负责三维表现。
这种结构便于快速调参、录制输入和复盘，也比浏览器刚体直接参与规则结算更适合作为
后续异步 PVP 的验证基础。Tone.js 在首次用户点击发射或声音按钮后启用音频上下文。

零件经济和教程进度位于 `src/core/progression.js`，三个出战槽位位于
`src/core/loadouts.js`；两者都不参与确定性战斗结算。
每个出战槽的 `customizations` 按基础零件 ID 保存 DIY 参数。改造后的质量、
质心和绕自旋轴惯量由 `AssemblyCalculator` 实时计算，其中惯量包含平行轴项。
材料所有权保存在 `ownedMaterialIds`；迁移旧存档时，已被任一配置使用的合法材料
会自动补为已拥有，避免升级后丢失已有改造。
本地存档键为 `spin-core-web-prototype-v2`；旧版
`spin-core-web-prototype-v1` 会在读取时保留金币、配置和已装备零件，并将原配置
迁移到第一个出战槽。

`BattleSimulation` 构造参数支持：

```js
new BattleSimulation({
  // ...
  diagnostics: true,
  logger: (message, telemetry) => console.info(message, telemetry),
});
```

每次有效碰撞会写入 `collisionLog` 并触发 `collision` 事件。`telemetry` 包含双方
碰撞前后的 `tilt`、`spin`、`imbalance`、`durability` 及对应变化量，方便导出后
分析平衡性。日志最多保留最近 200 次碰撞。

失衡、风险状态、发射高度、DIY 材料和组合惯量规则已有 Godot 对应实现。
Web 方形遗迹与石墩碰撞在 v3 加入，结构损伤/供能区/接触反冲在 v4 加入，
当前物理内核为 `2026.09.24-shared-v6`，组合版本为 `2026.09.24-shared-v6+launcher-v1`。
Godot 本地战斗已移植共享规则，完整 Web 美术／换装工作台和网络协议尚未迁移。

v5 已统一相机方向输入、发射预览、倾斜／自旋姿态，补齐惯量耗散、
方向性损伤、尖端滑移及有摩擦的圆盘接触。同帧双方淘汰和超时同分判平局，
结算支持原配置重赛。音频故障隔离于战斗推进，供能与接地状态来自实际求解结果。
评分条件可在改装页和陈列室查看；详细模型边界、测量与验证见
[前两轮实现](../docs/physics_v5_implementation.md)。
新增 `npm run verify:physics`（开发服务器与 Chrome），验证真实姿态、批量音效、
故障后连续推进及平局经济流程。

v6 统一可见地形和接触法线、圆场低边沿、遗迹开放边缘下落及实际装配支点高度。
摇杆使用小径向死区，固定 60Hz 规则步包含两个 120Hz 接触子步。
`exportState()`／`restoreState()` 支持完整中途状态，`battle-replay.js` 提供本地回放工具；
普通诊断 `snapshot()` 不可替代恢复数据。`npm run verify:physics-v6` 无需浏览器，
校验地形／恢复并生成 Godot 对照数据。原生运行方式和验收见
[第三轮实现](../docs/physics_v6_implementation.md)。
